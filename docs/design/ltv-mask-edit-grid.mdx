## 输出规格和当前边界

七个源节点都保存 `quality=2K`，源结果 `resourceMeta` 全为 **2752×1536**。这不是 OpenAI Images 的 `quality=medium`，也不能只用 `16:9` 代替。节点保留源 `2K` 和实测输出像素尺寸，原生 `size` 使用 `2752x1536`。

继续核对接口文档与原生提交链后修正了先前的判定：旧转换器无条件添加 `image-resolution-adapter-required`，即使模型目录已经明确登记蒙版和精确尺寸也不检查。原生插件本来按 `request.aspectRatio` 传递精确 size，运行时也已有蒙版、精确尺寸和引用数量校验；这是转换器未使用已有合同，不是影策缺少 2K 接入协议。

现在根据 `openai-image`、`maskSupported=true`、`size.values` 含 `2752x1536`、图片参考范围、完整提示词长度、输出数量及透明背景要求选取已登记模型。缺少匹配声明时保留空模型和完整严格参数，记 `channel-configuration-required`；禁用渠道也保持配置告警。不能选择只有 `16:9`／`2K`／`1024x1024` 声明的模型，不能减少输出数量或把像素档位偷偷写为 quality。首次生成和重试的原生校验不放宽。

专项新增了声明匹配与不匹配测试；加载实际 OpenAI Images 插件包的 Go HTTP 捕获测试，蒙版请求真实走 multipart `/v1/images/edits`，保留 `size=2752x1536`、`n=2`、原图和蒙版字节，quality 未被凭空设为 medium。测试使用本机假上游和固定响应，只证明原生传输，不证明真实供应商接受该规格或生成效果。

按冻结顺序重审 200 例后，36 处无条件尺寸适配误报解除；《格子》（排名 6）成为 `configuration-required`，整体适配准备计数由 40 变为 41，仍非上线验收。审计使用空模型目录，不能据此判断生产渠道缺失；没有执行付费模型生成。新报告为 `.local/featured-200/director-mask-200-audit/reports.json`，原报告保留。

清洗版图片替换必须同时给出原图与蒙版的一一对应 URL 映射。`remapLtvMaskEditMedia` 原子更新原图节点、引用计划与局部编辑元数据；`loadProductionCaseProject` 仅在调用者提供 `mediaUrlMap` 时使用该映射。本轮未新增经像素复核的清洗映射，未核验生产渠道的真实 2K 输出，也未执行付费生成、用户工程覆盖或发布。

## 无入边的透明底图擦除

源 `3fmef38tastmc.js` 的 `handleGenerateErase` 只提交 `originImage`、数量、质量、场景、模态及可选比例／尺寸，不要求 `imageList`。排名 50 三个擦除节点无入边、四类参考列表为空，所存 `originImage` 本身就是带透明擦除区的底图，不是生成结果。

已取得三张原始 PNG 并解码：均为 RGBA、622×350，透明像素分别为 23,401、70,739、795，其余 alpha=255，没有中间透明度。图片已逐张查看，尚未作为清洗发布资源。输入尺寸 622×350 与节点要求的输出 2752×1536 分开保留，不将低分辨率输入冒称为 2K 原图。源字节 SHA、透明度和原快照哈希在 `.local/featured-200/standalone-erase-source/receipt.json`。

主转换器现仅对没有任何入边、没有其它参考、参数完整的 `erase/image2image` 补入 `originImage` 参考，经原有内嵌素材节点路径建立独立输入及连线。该图片同时作为原生 image 和透明 mask；保存的生成结果不参与输入恢复。有入边的原图＋蒙版路径保持原样；缺原图、redraw、畸形／冲突参考和含凭据地址不补位，未知制作参数仍阻塞。

新增先失败后通过的主转换器测试覆盖输入、蒙版、输出区分、调用者快照不变、清洗地址原子替换和负例。连同原转换器、参考、分镜及导演台回归，共 59 项前端测试／215 个 Bun expect 通过，TypeScript 检查通过。Go 插件运行测试新增相同图片同时作为 image/mask 的 multipart 捕获，通过真实 `runImageTask` 与现有打包插件，保留精确 size 和数量；仍是本机假上游协议证据，不是付费生成或视觉等价验证。
