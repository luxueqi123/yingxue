### 候补 336：H3-Max 与现有 AutoDL H3 不可仅按名称匹配

### 时间线正分贝：预览与导出不是同一个消费合同

- 已从本地原始 chunk 提取并执行原 `A/D/R/_/L/P/F/O/j` 函数及原常量，未按经验重写后自测。源预览在正分贝区间使用 `1 + db / 20 * 4`，不是通用的 `10 ** (db / 20)`：+6 dB 为 2.2 倍、+12 dB 为 3.4 倍、+20 dB 为 5 倍；通用换算对应约 1.995、3.981、10 倍。-60 dB 在源预览为静音。
- `toServerModel()` 将 `F(clip)` 得到的原分贝随每个片段提交，轨道音量另行限制在 0–1；远程 `media-platform / compose` 消费 videoList、audioList 与轨道音量。前端请求证明了字段送达构造器，没有证明远程编码器使用预览的正增益曲线。
- Premiere 工程导出另有 `Audio Levels` XML，将片段 dB 与轨道音量转换的 dB 相加并限幅；这是单独的工程导出路径，不能冒充远程视频合成消费证据。
- 影策原生播放／FFmpeg 导出已能接收大于 1 的 volume，但目前统一的线性音量字段尚不能证明同时忠实对应上述源路径。因此保留排名 101、186 的正分贝核验门禁，不改模型、音量、排序或上线计数。下一步应寻找本地合成服务消费者或同输入的真实源导出对照，不能仅删去门禁。
- 可复算证据：`.local/featured-200/audio-positive-source-contract/audit.mjs` 与 `receipt.json`，包含两个源文件 SHA、精确摘录偏移、原函数执行结果及请求链。未读取图片、发送生成任务或写生产数据。
- 同一审计逐份核对排名 101、186 的冻结快照 SHA：实际正增益分别为 +12 dB 和两个 +0.310409 dB 片段。排名 101 的第二条时间线还保存了短于片段末端的总长（106 秒对 109.009 秒）。原 `applySavedClipLayout` 按 `Math.max(eS(clips), savedDuration)` 扩展该短总长，故原生适配已移除这一错误拒绝，保持所有片段和源快照不变；长于片段的尾部空白仍明确待映射，不直接丢弃。新增回归先复现失败后通过；正分贝门禁独立保留。

### 扩图节点的具体协议边界

- 全冻结范围共 8 个工程、16 个 `expand-image` 节点；12 个请求 2K、4 个请求 4K，全部 n=1、image2image，重试身份均为 nebula-ultra。逐份冻结缓存 SHA 已核对，没有读取原图、下载远程素材或修改参数。

本地原前端 `0zme995kos_wy.js` 的请求构建逻辑先解构 `fineTuneType` 与 `fineTuneModels`，不是把这两个字段直接透传：
