# LTV Midjourney 原参数与输出合同核查

## 结论与范围

这是冻结精选 200 项中的协议接入核查，不是 Midjourney 已接通或工程已上线的声明。源工程保留，不用删参数、改版本或重复提交来消除告警。

当前本地插件清单核对了 106 份源码 manifest 和 103 个包，未找到以 Midjourney／MJ 标识声明的专用 Provider。**这不等于影策不能接入**：影策的统一任务、媒体引用和声明式 Provider 是实现入口；但通用 HTTP 能力并不自动证明某个第三方的请求、轮询与输出合同已经兼容。

影策既有协议文档也明确区分模型族、厂商原生协议和第三方网关，特别指出 Midjourney 的第三方接口不能命名为统一官方接口。参见 [协议全景](model-request-protocol-landscape.md) 和 [插件平台现状](plugin-platform-and-marketplace-research.md)。这两份文档是历史审计，实际能力仍以当前代码、包清单和执行证据为准。

## 已核对的公开网关合同

### Midjourney Proxy

只读核对 [novicezk/midjourney-proxy 的 API 文档](https://github.com/novicezk/midjourney-proxy/blob/0be95a9187da5c9c59442c116b2998376dec3163/docs/api.md)，固定提交 `0be95a9187da5c9c59442c116b2998376dec3163`。

- 创建返回 `code=1` 或 `22` 表示已接收，`result` 为任务 ID；不能只依据 HTTP 200 判断提交成功。
- 文档中的任务结果使用单个 `imageUrl`，并有独立的 U1–U4 变化接口。
- 该文档不能证明原 LTV 的四张输出可以直接等价映射；单个 URL 不能冒充四个输出，也不能默认为需要额外四次放大请求。
- 文档不是原 LTV 后端协议，不能据此推导它与源模型版本、参数优先级完全一致。

### APIMaster Midjourney

只读核对 [Midjourney v8.2 / Niji 7 接口文档](https://apimaster.ai/docs/en/api/images/midjourney-imagine)。这是第三方网关，不是 Midjourney 官方接口。

- 创建为 `POST /v1/midjourney/generations`，查询为 `GET /v1/tasks/{batchId}`。
- 文档声明 `midjourney-v8.2` 和 `midjourney-niji-7`，不能把源 V7、V8.1 静默升级为 V8.2。
- 支持结构化 `stylize`、`weird`、`chaos` 和参考图；文档明确结构化参数优先，并拒绝使用 `--v`／`--niji` 覆盖模型版本。源提示词存在版本标志，因此并非零转换直连。
- `repeat` 表示创建多个任务，不等于源 `count=4` 的四张结果；不得把它设为 4 来制造看似相同的数量或增加未确认费用。
- 创建返回 batch ID 和子任务 ID；结果有 `data`、`tasks[]`。必须核对每个子任务，不能把部分成功当全部成功。
- `502` 携带 `X-Task-ID` 或查询 `pending_timeout` 时，文档要求保存原 ID 并继续查询，不自动重发。
- 文档示例不足以证明四张独立输出的精确形态；目前没有真实渠道、付费调用或结果形态验收。

## 按影策既有架构落实的下一步

### 已补核的源前端合并合同

源消费方 `0zme995kos_wy.js`（SHA-256 `d9039ddfc7bd53f044409f696ddcd48b61674dd3bb25e9cccf9a022ac7a2ae64`）明确给出字段合并顺序：基础字段 → settings → 过滤后的 advancedSettings → effects／LoRA 增补。underscore 字段被排除，显式数字 0 不因假值被删除；提示词命令和这些字段都继续送往源后端。**该段仍不能证明后端对命令和独立参数的优先级**，不据此前端对象合并顺序猜测网关可直接替换。

`isMidjourneyStyleOverrideModel` 只包含 `mj-v7`、`mj-niji7`、`mj-v8.1`；这些版本存在非空 `fineTuneModels` 时，源前端排除当前 schema config 声明的高级字段。`mj-v8.2` 不在此集合内，不能把旧版风格覆盖策略推广过去。全冻结范围 1,760 节点中 **13** 个走该覆盖分支，**1,747** 个保留控制字段。排名 170 的 **25** 个 MJ 节点全部不走覆盖分支，`stylize/weird/chaos` 是真实请求要求，现有告警不能靠删除这三个字段归零。

已保存输出也不都等于声明 count：**1,506** 节点保存 4 个 URL，**251** 保存 1 个，**2** 保存 3 个，**1** 没有 URL；**8** 节点存在重复 URL。这里只核对原快照数组和精确 URL 字符串数量，没有读取历史图片或推断网格内容。单图可能是保留结果、不同历史状态或其他语义，不能自动补三张、复制 URL 或猜测为拼图；缺少相应结果消费证据时保持原状态。
