# 范围与当前结论

仅对冻结精选 200 的 `locked-source-cache` 做只读调查，未修改来源、发布名单或工程。13 个案例含 17 个 `video-clip` 节点；16 个有 `clipTimelineData`，共 113 个片段（107 视频、6 音频），全部源节点、入边及媒体 URL 可交叉定位。原生独立音轨预览和导出实现不等于已完成这些节点的导入。

首个受影响案例为冻结排名 35、`case-7000d919940946e0bc4140bf4b3da3cd`；节点 `9165be87-f1fe-4659-bdc2-316fdba8a70e` 的 `action=video_clip_resource`，只有 3 个 `params.videoList` 引用及入边，没有 `clipTimelineData`，输出 URL 也为空。缺失的是原剪辑时序和裁切证据，不能用成片地址或顺序拼接猜造。

## 已保存字段与接入边界

| 来源 | 原生目标 / 后续核验 |
| --- | --- |
| `clips[].sourceNodeId`、类型 | `TimelineClip.nodeId` / `kind`，交叉核验节点及入边；复制时重映射 |
| `startTime`、`duration` | 秒转毫秒至 `startMs`、`durationMs` |
| `sourceOffset`、`sourceDuration` | 秒转毫秒至源内裁切，校验实际源时长边界 |
| 轨道索引、`zIndex` | 稳定轨道 ID、kind、order；不丢音轨 |
| `videoAudioMuted`、`audioTrackMuted` | 轨道静音；`embedAudioMuted` 单片段静音不能误作用于整轨 |
| 轨道 volume 与片段 `decibel` | 原站当前预览把轨道 volume 钳制到 0–1 后乘片段播放增益；正 dB 使用自定义映射，不直接套标准 `10^(dB/20)`；导出消费方仍需核验 |
| `cropRange` | 源编辑器的选区及独立 `exportCrop` 操作；不是已证明的整条时间线输出范围，仍需保留相应编辑能力 |
| `totalDuration` | 与片段末端交叉核验，不盲信摘要 |
| `currentTime`、`scale`、`scrollX` | 编辑视图状态，不能混入内容时序 |
| transform、role 等 | 单位变换与未知语义分别处理，不统一丢弃 |

实测发现原快照的浮点秒直接乘 1000 会产生小数毫秒和极微小黑场：后端合同使用 int64 毫秒，旧直接转换也会被 JSON 解码拒绝。解析器现在按绝对起止边界量化毫秒，避免逐片段独立舍入累计误差；源时长向上取整到毫秒，仍校验原始裁切与量化后边界。排名 52 的 8 个连续片段不再生成 7 段浮点误差黑场，总时长为 40,333 毫秒。

## 节点入口、复制与本地持久化续接

解析通过的剪辑节点现在映射为拥有独立时间线的原生视频节点；空输出明确显示“独立剪辑”，工具栏“进入剪辑”打开该节点自己的时间线。保存仅写该节点 metadata，不修改项目时间线，也不向共用源视频回写另一条剪辑的字幕。模型请求入口拒绝把剪辑节点当生成节点。生成新片段成功后保留输出节点，同时将媒体引用写回原剪辑节点，让其既有引用边继续指向该剪辑的输出。

案例复制对嵌套时间线复用严格校验，重映射源节点与片段 ID；缺少源素材时拒绝，不静默删片段。画布内复制深拷贝时间线，已复制源节点重映射，未选择复制的源节点保留原引用。原生持久化编解码及内容哈希测试已覆盖嵌套时间线；不是后端保存验收。

## 原站预览消费方补查

本地前端 `chunks/3ynelx_m_i-cu.js` 中的 `applyAudioTrackOutputGain` 和 `applyVideoAudioElementVolume` 均使用 `clamp(trackVolume, 0, 1) * O(clip)`；静音优先归零。有 Web Audio GainNode 时媒体元素 volume 为 1，增益交给 GainNode；缺失 GainNode 才把最终增益钳制到 1。因此源数据的 `audioTrackVolume=3.98` 不代表播放时再乘 3.98，不能与片段 `+12dB` 直接叠乘。

`O(clip)` 先经 `P` / `R` 将保存字段转为有效推子 dB：非正值使用 `10^(dB/20)`，正值使用 `1 + clamp(dB, 0, AUDIO_FADER_DB_MAX) / AUDIO_FADER_DB_MAX * (AUDIO_PLAYBACK_LINEAR_MAX_RATIO - 1)`。同文件波形绘制另使用标准 dB 指数；不可从波形函数反推真实播放增益。仍需定位配置常量、导出请求及快照对应版本，再实现与原站一致的转换。未据此提高适配通过计数。

续查配置文件 `1ufi8v8afcnfs.js` 得到最小／最大 dB 为 -60／20、最大线性增益 5、静音推子区间 0.02、0dB 推子位置 0.3。`L/P/R/O` 表明 -60dB 落入静音区，实际增益为 0，不是 0.001；+12dB 的预览增益为 3.4，不是标准指数 3.981。解析器已映射非正分贝，正增益在原生预览等价实现前保持明确阻塞。

后续原生增益链已实现并验证：`TimelineMediaGain` 为同一媒体元素复用一次绑定的 Web Audio 图，卸载断连，避免 StrictMode 或换源重复 createMediaElementSource。音频和两处视频预览均接入；同源／允许 CORS 的真实本地测试媒体实测放大、回落、静音，后端 FFmpeg 实测同幅度输出。此项解决的是宿主能力缺口；原站完整导出消费方仍未核对，正 dB 源片段仍未放行。不能由宿主测试倒推原站导出采用与预览同一增益公式。

`eB/ez` 表明非空逐轨静音数组优先于旧整体静音字段，而非两者 OR；空数组才回退整体值。已按实际消费方实现并覆盖矛盾字段测试。`exportCrop` 明确从选中或包含选区的单片段取源内时间并调用 `exportCroppedVideo`；因此先前把 cropRange 视为整条时间线输出区间的推测已纠正，后续不按该推测裁掉整条工程。

## 原站导出请求已定位，服务器增益运算仍未证明

同文件 `toServerModel` 将 `F(clip)` 的原始有效 dB 写到音频片段 `decibel`，视频片段使用 `eY(state,clip)`（静音时写最小 dB）。轨道音量在返回值中分别钳制到 0–1。随后 compose 提交将 videoList/audioList 连同 videoVolume/audioVolume 发给 media-platform；没有在浏览器套预览的正 dB 线性映射。`toProjectExportModel` 同样保留 dB，XML 音轨导出还会加上轨道音量的 `20*log10(volume)`。

因此原站存在“预览线性增益”和“导出 dB 请求”两个不同合同。前端证据尚未证明其服务器如何解释 dB，正增益片段继续明确待核对，不直接以 3.4 或 3.981 猜测整条工程导出。源文件 SHA、符号偏移与片段证据保存在 `.local/featured-200/source-export-contract-evidence.json`，未访问账户或提交生成任务。

## 保存选区恢复合同纠正

原前端 `3ynelx_m_i-cu.js` 偏移 377988 的恢复消费方明确调用 `applySavedClipLayout(savedClips, {..., cropRange:null})`。保存的选区不参与工程恢复；此前把它列为能力阻塞有误。解析器现在接受并忽略该临时选区，不修改源快照，真实裁切仍由每个片段的 sourceOffset/duration 保留。9 条含选区的源时间线逐一回放原恢复表达式，8 条解析通过，另 1 条仍因正分贝导出合同待核对而阻塞。证据 `.local/featured-200/crop-restore-evidence.json`。

排名 59 的尾部裁切另暴露独立取整造成 1 毫秒越界：保留时间线绝对起止，仅在原始裁切合法且源起点偏差严格小于 1 毫秒时使用相邻源毫秒；不扩大源总长，也不放过原始越界。新增回归先复现失败，再通过；相关 23 项测试、126 断言及 TypeScript 检查通过。
