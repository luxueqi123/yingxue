## 关节转换

生产转换器为 `web/src/lib/canvas/director/ltv-director-pose.ts`。输入必须是尚未应用姿态的源 GLB 与 `jointAngles`，输出原生 `rig`、绝对 `boneOverrides` 和 `neutral` 姿势；不原地修改 GLB，不用原生站姿或默认演员代替源效果。

- 源骨骼选择先按遍历顺序匹配任意精确别名，再按遍历顺序匹配包含别名。不是按别名列表优先级查找。5 个实际模型中，body 选择 `Root`，torso 选择 `Spine01`，不是骨盆和 `Spine02`。
- 源 `lN` 将传入 Euler 的三个分量全部取反，并计算 **静置四元数 × 增量四元数**。身体／躯干／头部使用 YXZ；手臂／大腿使用 ZXY；肘／膝使用 XYZ。左右侧符号不同。
- 源默认躯干前倾 2 度、头部 nod 为 -10 度，双臂 raise 为 -5、straddle 为 7，肘 bend 为 15；不是全零。转换保留这些默认值，显式零也保留。
- 原生绑定不存在、不唯一、源关节重用同一骨骼或输入数值畸形均报错；不会为了增加成功数默默跳过。

## 当前验证

7 项骨骼／姿态单元回归、37 次断言和 TypeScript 检查通过。验证范围包含根骨／躯干选择、静置旋转乘法、组合角度、JSON 往返、原生骨骼求值、原对象不变及错误分支。

浏览器差分夹具从已校验 SHA 的消费方提取原 `lN`、`lL` 与骨骼选择函数作为独立对照，原生一侧实际调用上述转换器和 `resolveDirectorBoneRotation`。对冻结工程 23 个真实角色，加上每种模型 3 组正负组合角度共 15 个探针，逐一比较所有蒙皮顶点位置；38 组最大误差均为 0。脚本错误和意外网络请求均为 0。证据为 `.local/featured-200/director-browser/receipt.json`；生成对照脚本为 `prepare-director-pose-oracle.py`。

这个差分证明的是**关节局部变形**，不是源场景完整世界坐标、灯光、机位或动画等价，也不是整站运行验收。

## 角色模型准备与二进制回读

新增 `web/src/lib/canvas/director/ltv-director-actor.ts`，接收调用方独占、未施加姿态的 GLB 模型，按源合同处理后返回原生对象与模型。调用方共享模型须先克隆；此函数不执行上传，不自行决定发布地址。

- 根据 `skipNormalize` 保留原高度或规范到 1.75，居中落地后设置模型 Y 修正 -90 度；角色级位置和 XYZ 旋转单独保留，逐轴 scale 乘 uniformScale。
- 应用源姿态后，按源消费方的“蒙皮包围盒 → 世界坐标 → 角色局部坐标”规则计算接地偏移，保留 0.0005 的原阈值。倾斜角色和非均匀缩放时，不能用单个局部顶点最低值代替这个包围盒合同。
- 克隆材质后修改颜色，保留纹理、粗糙度等属性，不改共享原材质。角色阴影开关保留，receiveShadow 按源合同关闭。
- 输出 `kind: model` 与现有 `modelNormalization: preserve-source`，避免原生演员材质替换和再次 fit。模型仍包含原骨骼，原生骨骼覆盖照常可用；没有新增运行时 schema 或旁路协议。
- 缺明确姿态、畸形变换、退化缩放、SAM、程序人偶与动物不在该入口中被默默替代；当前只承接有证据的原 GLB 角色。

真实 Edge 中每个角色都经过 **准备模型 → GLTFExporter 二进制导出 → GLTFLoader 回读 → 原生 preserve-source → JSON 对象回读 → 原生骨骼求值**，再与原消费方归一化、姿态、角色变换及落地结果逐顶点比较。23 个真实角色和 15 个正负组合角度／倾斜／非均匀缩放探针共比较 1,101,725 个顶点，最大世界坐标距离误差为 `5.181144546835403e-7`；颜色回读全部一致，浏览器错误及意外外网请求均为 0。10 项专项回归、88 次断言和 TypeScript 检查通过。

23 个角色的准备候选已保存于 `.local/featured-200/director-actor-candidates/`，按 SHA 去重后为 7 份 GLB；逐角色引用字节合计 50,045,268，不是实际去重磁盘占用。候选回执保存原生对象、文件 SHA、逐角色误差、`verified` 与 `published: false`；全部文件 SHA 已从磁盘复核。**发布数为 0，不计作 23 个案例完成。**

## 静态摄影机与场景坐标

`web/src/lib/canvas/director/ltv-director-camera.ts` 现在按源全画幅截图路径输出原生静态摄影机，场景矩阵遵循原 XYZ 旋转、平移和 `[0.1, 10]` 范围的场景缩放。摄影机位置与目标同时经过该矩阵，不只缩放演员。

- 普通空 `lookAtTarget` 使用保存的 `lookAt`，不把残留 `cameraRotation` 应用到画面。只有 `__none__` 模式按源三角函数计算视线并额外应用 Z 荷兰角。
- 角色目标使用源角色逻辑位置加固定 `1.2` 高度，再转为世界坐标；不是角色模型身高或带 scale 的头顶。空对象目标直接取位置。未解析目标、分组目标与动态 follow 不会被静态默认视线替代。
- 源四元数分支保留其实际世界朝向。正 zoom 通过有效 FOV 换算接到原生单位 zoom，near/far 保留源截图合同的 0.1/2000。
- 输出已有原生摄影机结构，经 JSON 回读和原生 view-up 求值后，无需增加摄像机 runtime schema。focalLength 与 aperture 只是原生编辑器字段，不宣称源站保存了这些光学元信息；本次对比的渲染合同是 fov、near/far、位置和朝向。

从已校验源脚本提取原 `captureFromCamera` 相机构建函数、`f4`/`f6` 朝向分支及目标解析分支作为对照。冻结 5 个真实机位，加 5 个 zoom／荷兰角／场景旋转／四元数探针，各按 16:9、9:16、1:1 三种比例比较世界矩阵和投影矩阵，共 30 组；最大元素误差 `4.440892098500626e-16`。5 项专项测试、15 断言及 TypeScript 检查通过。证据为 `.local/featured-200/director-camera-receipt.json`，同目录保留 `prepare-director-camera-oracle.py`、`verify-director-camera.ts` 和去掉截图正文的机位输入投影。

上述仅证明静态全画幅相机，不包含源编辑器侧栏扣除后的 viewOffset 裁剪，也不证明动画追踪、整体场景合成或线上保存重开。

4 个源导演台节点实际有两件道具：排名 50 的圆柱和排名 170 的圆环。新增 `web/src/lib/canvas/director/ltv-director-prop.ts`，按消费方 `cr`、`cn` 和 `c4` 保留它们的具体几何，而不是套用原生默认尺寸：

- 圆环为半径 0.34、管半径 0.12、径向 20 段、管向 48 段，网格局部 Y 偏移 0.46。
- 使用源色、roughness 0.62、metalness 0.04；普通道具不额外开启阴影。源对象位置、XYZ 旋转、逐轴 scale × uniformScale 在其外层，场景矩阵再左乘对象矩阵。
- 输出保留原坐标的骨架无关 GLB 模型。未知几何和外部媒体变体显式报错，不像源显示兜底那样创建一个小方块后宣称接入。

## 原生环境运行时接线

原生视口过去无条件绘制默认地面，灯光枚举不含源站半球光，默认 ACES 色调映射也不同于源 WebGLRenderer 的 NoToneMapping。现在这些差异有明确原生入口，而不是在资产中调色抵消：

- `DirectorScene.groundVisible` 仅控制原生默认地面，缺省保持旧行为，显式 false 才隐藏；源透明地面作为独立 preserve-source 模型承接。
- `DirectorScene.toneMapping` 可指定 none 或 aces，缺省保持原生默认。实际 `DirectorCanvasSurface` 将 none 接到 R3F `flat`，不只写入元数据。
- `DirectorLight` 增加 hemisphere、groundColor、shadowNear、shadowFar；真实 `DirectorSceneEnvironment`/`DirectorLightView` 渲染它们，灯光检查器也有半球光和下半球颜色入口。旧光型及缺省阴影裁剪范围不变。

`ltv-director-environment.ts` 按源初始化函数创建环境光 1.05、半球光 0.85（下半球 `#2c3140`）、主光 1.2 与补光 0.75；灯光留在世界空间，不跟着 contentRoot 缩放。源地面 40×40、`#0d1829`、roughness 0.9、透明度与可见阈值原样保留；groundHeight 先除源场景 scale，再乘场景矩阵。额外原生环境光设为 0，避免重复打光。

真实 Edge 夹具加载的是生产 R3F 环境组件，阴影开启、NoToneMapping 生效。地面可见／隐藏两种状态分别与源初始化函数构造的灯光地面进行 640×360 RGBA 逐字节渲染比较，两组差异字节均为 0；截图已查看，无脚本错误或意外外网请求。环境、视图、模板、会话和恢复专项共 152 测试／1,024 断言通过，类型检查通过。初次类型检查发现 flat 引用了错误作用域，修正为实际 sceneProps 后重新通过，没有忽略错误。

证据 `.local/featured-200/director-environment-browser/receipt.json`、`environment.png`、`.local/featured-200/director-environment-regression.log`。此夹具证明环境组件接线，不是整套导演台页面、灯光检查器交互或源场景合成验收；这些新可选 JSON 字段没有新增后端数据库表或列。源全景、高斯环境仍明确报未接入，不用纯色天空替代。
