# v1.2.9 映雪整合发布

正式网站为 https://tianyayingxue.cn 。本次在独立工作树融合上游 v1.2.9 与映雪二开，原开发工作区未被覆盖。后端发布源码提交为 `659b49053763ae2a4d531b553d350ca934338923`，前端随后发布原片缓存修复 `97c60ae506981acfa57ed63d89d6fdb46cd2d6e0`；均包含整合提交 `78076fd2`。后续文档提交不改变运行二进制。

## 保留与整合

- 保留已确认首页、大厅、映雪品牌、原画布、LTV 案例、Skills、提示词、素材及制作入口。
- 大厅输入框 560×48，聚焦展开为 560×114；草稿提交进入真实画布，Agent 仅预填，不自动创建生成任务。
- 钱包对接插件订单，保留云猫支付宝／微信、赠送展示和历史订单续付；不可关闭的供应商订单不提供虚假关闭操作。
- 保留 GPT-6 真实用量计费、退款幂等、CTMO/Wan、媒体工具链和文本模型映射。
- 旧无签名直接到账接口关闭。旧订单影子行排除重复入账；新插件交易唯一约束已实测。
- 保留 AutoDL 原有流程，融合上游 v2.1 包；Agent 支持 base64 技能包及完整 inline 技能正文和文件。
- 生产使用外观配置设置映雪品牌、SEO 标题及页脚，不伪装成上游品牌。

## 生产切换与数据

最终发布镜像为 `yingxue-web:v129-20260912-media1`、`yingxue-backend:v129-20260912`。后台版本为 `v1.2.9-yingxue.20260912`。

维护窗口内先停止旧 Web／后端，再备份最新数据库与 backend-data。针对新镜像 app 用户，仅调整专属数据卷的文件归属，不更改加密文件内容。迁移与启动前后核对账号密码字段、余额、账本和旧迁移历史指纹，结果一致；65 笔历史订单全部迁入插件表。

最新备份已真实恢复到无外网隔离数据库：12 个用户、14 个积分账户、119 条账本记录、65 笔旧订单。备份内容和凭据不进入代码仓库。

## 案例媒体

完整目录包含 1,024 条案例。原始成片链接始终保留；服务器缓存是原片副本，不使用低清预览替代。缓存清单仅在所选 100 份原片的大小与 SHA-256 全部验证后原子发布；`metadataCount` 必须与完整案例目录一致。

100 份原片已全部完成校验并发布，共 39,390,362,544 字节，包括 88 个 MP4、12 个 MOV。前端实际清单合并函数验证通过，保持 2,512 条制作资源、1,024 条案例及原始成片 URL 不变。

最终公网检查：100 个文件的 HTTP 状态、完整大小及媒体类型全部通过；3 处中段 Range 返回正确的 206、Content-Range 与 1,024 字节正文。本轮检查没有网络重试。媒体证据为 `production-media-http-receipt.json`、`production-media-contract-receipt.json`、`production-video-play.json`。

公网验收曾发现 CDN 返回 Range 响应头后正文超时，源站 HTTPS 则正常。媒体响应改为 `private, no-store`／`CDN-Cache-Control: no-store`，播放与下载地址携带文件 SHA-256 避开旧缓存；媒体文件没有转码。新镜像构建与 Nginx 检查通过，真实 Edge 已加载原片并跳转中段播放。旧源链接回退仍保留。

这是原片交付验证，不代表所有浏览器都支持所有源编码；原文件含 H.264、HEVC 与不同音频编码，不能将抽样播放写成全部平台兼容。

## 首页性能与源站访问限制

前端性能版保留全部制作功能、原素材与既有账号配置，仅调整资源加载和缓存：

- 三张首页展示图片使用 WebP 副本，合计约 3.71 MB 降至 0.247 MB。背景视频原片保留，桌面播放副本约 4.91 MB，手机约 1.70 MB。
- 外观配置与应用代码并行下载；独立电影主题的公开首页先呈现，外观配置随后同步，配置未返回时不覆盖 HTML 中的映雪品牌信息。其他路由仍等待配置完成。公开首页不再误预取创作页，登录弹窗按需加载，内置插件在已认证创作环境或公开分享画布渲染前注册。
- 错误页、认证布局按路由加载。取消手工共享组，使用依赖图自动分包，避免页面之间通过公共分包提前引入制作模块。
- 实际生产匿名首页脚本从 42 个、约 2.04 MB 降为 19 个、约 0.67 MB。此数字为压缩传输量，不等同于加载时间。
- 版本化网页展示副本及内容哈希脚本长期缓存；普通业务 API 明确为 `private, no-store`。原片、SSE 与公开分享专属规则继续保留。

Cloudflare 代理保持开启。宿主机网站反代依据官方公开 IP API 获取的 22 个 IPv4/IPv6 网段限制回源，允许本机检查，证书验证路径单独保留。当前物理网卡直连源站的首页、健康接口和展示图片均返回 403；通过 Cloudflare 的域名健康检查为 200。该措施是站点 HTTP 访问控制，不是网络带宽层清洗，也不是仅属于本站的回源身份认证。未修改 SSH、面板端口、DNS 或客户端代理。

类型检查、生产构建、Nginx 配置检查通过；工作区预取及外观请求失败专项共 5 项通过。线上前端配合隔离业务 API 验证输入框 560×48→560×114，提交进入原 Canvas，草稿保留，无真实项目写入或生成。证据为 `perf-workspace.json`、`origin-denial.json` 和 `performance-perf4-*.json`。

最终性能版首轮新 CDN 缓存样本为 5.35 秒；缓存命中、全新浏览器上下文两轮输入框可见为 4.05／3.84 秒，FCP 为 3.59／3.37 秒。背景视频均完整缓冲，观察期约播放至 14.7 秒，两轮各掉 3 帧，无未完成请求。原始基线输入框可见为 4.94 秒，脚本约 2.04 MB。不同时间的公网线路会波动，不能把以上样本当作三网保证或精确归因的测速实验。

中间版本的冷缓存 37.95 秒及缓存命中 5.59／5.61 秒样本也保留在本地证据中；未用中间结果宣称提速成功。CDN 路径与客户端访问链路仍需继续处理；Cloudflare 管理权限、线路或付费方案没有在本轮变更。

前端最终性能镜像为 `yingxue-web:v129-20260912-perf6`。perf4 完成上述性能改造，perf5 修正初始 HTML 标题，perf6 修正外观请求失败时误用上游默认品牌覆盖当前页面的问题；这两次品牌修正未改变布局、制作功能和媒体副本。服务器发布目录保留各版 Compose、构建日志、切换收据及源站限制前的反代配置。前端回退只切换 Web 镜像，不回滚当前数据库；反代访问限制单独恢复备份并验证 Nginx 后重载。

## 数据回退边界

切换前保存了实际运行容器的 Web／后端镜像快照，包含运行热修；不能仅凭旧 Compose 标签回退。数据库迁移失败或新后端未就绪时维持维护状态，先检查日志再恢复。

网站重新开放后可能出现新订单、新账本与新项目，禁止直接用切换前备份覆盖当前数据库。需要回退时先停止写入并再次备份，核对新增交易和数据，再决定仅回退应用还是做受控数据修复。不要把直接安装原上游镜像当作二开更新。
