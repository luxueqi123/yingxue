# 会员与周期积分

账号菜单的「会员中心」提供月付和可选年付购买、当前权益、每期积分及购买记录。后台「会员套餐」管理价格、每月积分、同时进行的任务额度、存储容量和积分宽限期。未上架套餐仅管理员可见。系统不自动扣费续期。

## 套餐与价格

月付即可获得套餐列出的权益。年付可选择关闭，开启后一次支付12个月，积分仍逐月发放。后台提供低门槛价格参考草稿，保存或上架由管理员明确操作。基础兑换沿用1元100积分，发布校验会员赠分不超过25%，年付按12期总积分核算；不额外叠加模型折扣。此校验不能代替存储、支付手续费及实际模型成本核算。

每次订单固定套餐版本与完整权益，编辑或下架套餐不追改既有订单。续购顺延至已有会员结束；换档同样在下一段会员期生效，当前版本不支持立即升级或按比例退费。

## 周期与权益

按北京时间购买日的原始日历锚点计算每月边界：31日购买可落在2月末，3月仍回到31日。后台每分钟扫描并补齐到期周期，钱包读余额和扣费事务也会同步；过期的历史周期只记到期批次，不把已失效积分补为可用余额。

并发权益表示可同时处于排队或运行的任务总数，不代表上游保证的实际并发或优先队列。会员容量与原有基础容量取较高值，再叠加单独购买的扩容。到期保留文件，沿用超额7天后只读规则。

## 积分账务

历史充值、兑换、奖励及永久余额保留现有账本，不新增到期日。会员积分单独记录批次，按先到期先使用的顺序预扣，再使用永久余额。账户总余额仍是钱包的唯一汇总。

预扣冻结的积分跨过有效期仍保留，成功后消费；失败按原来源返还，永久余额仍回永久余额。已过期会员批次首次返还建立24小时补偿批次，同来源的后续返还不延长截止时间。补偿批次过期后再次失败，按原截止时间归还并在同步时到期，不能通过反复失败延长积分寿命。

周期、支付回调、账本和批次分摊均在现有事务中完成。订单与周期分别有唯一业务键，重复通知或多实例扫描不能重复发放。套餐和月年商品连同审计同事务保存；版本冲突返回409。

## 接口

以下路径均位于 `/api`，使用现有Cookie登录与业务信封：

| 方法与路径 | 权限与用途 |
| --- | --- |
| `GET /membership` | 本人当前权益、公开套餐、订阅记录及有效/冻结积分批次 |
| `GET /admin/membership/plans` | 管理员读取全部套餐及草稿 |
| `POST /admin/membership/plans` | 管理员创建，`version=0` |
| `PATCH /admin/membership/plans/:id` | 管理员更新，必须提供当前`version` |
| `POST /payments/topup-orders` | 复用支付，提交服务端提供的月/年商品ID，不接受客户端价格 |

## 迁移和发布

Schema110追加4张会员表，为账户增加会员标记，为商品与订单增加权益快照。原余额、冻结和历史订单金额不改写。生产关闭自动迁移时必须先使用同版`migrate-schema up`和`verify`。发布前保留数据库恢复快照并演练PostgreSQL迁移。产生会员批次后，旧程序不理解批次分摊，禁止直接回滚旧二进制后继续扣费。

当前范围不含模型专属次数卡、积分活动商城、自动续费、会员退订退费或立即换档。真实付费与上游生成须按业务授权单独验收。
