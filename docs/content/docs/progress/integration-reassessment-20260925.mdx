## 全线合同核对

### 旧归档工程的素材复制接线

旧归档仍使用现有专用转换器，不向官方 LibTV 导入 API 提交另一种结构。需要自动归属素材的工程，在已有哈希校验的工程 JSON 中附带 `mediaAssets`；不另设无版本的旁路下载清单。单项字段为：

- `source`：工程里原始媒体地址，精确匹配节点内容或局部编辑源图／蒙版引用。
- `kind`、`mimeType`、`bytes`、`sha256`：媒体类型、实际 MIME、正整数字节数和文件 SHA-256。
- `path`：`/production-library/case-media/{caseId}/{sha256}.{extension}`，限定当前案例和实际文件格式，不接受任意外链或目录穿越。

清单必须覆盖工程全部图片、视频、音频以及局部编辑蒙版；拒绝缺项、重复源、类型错配和同一路径字节数矛盾。清单随工程快照参与已有目录 SHA 校验；修改后须重新登记工程摘要。此合同证明文件身份，不证明清洗、全片影音或生成效果已经验收，发布仍遵守原有门禁。

`useProductionLaunch` 在用户确认后把清单传给已有 `materializeNativeCaseMedia`；服务在任何上传前检查固定参考／蒙版完整性、读取全部唯一文件并验证 MIME／字节数／SHA。通过后复用现有上传 API、账号隔离与幂等键，同步普通媒体及局部编辑引用；旧账号 `assetId` 清空，由原有保存链建立当前账号素材关联。只读预览不上传，中途失败不删除可能已被其它工程引用的资源。未登记清单的历史工程保留原有读取行为，不把外链工程说成已完成素材归属。

当前为代码接线及专项回归通过；第 3 工程公共快照尚未登记完整发布素材清单，未自动启用此路径，独立测试账号的资源 ID 不写入公共快照。

本地文件服务复用现有 `.local/ltv-case-library/manifest.json`：`entries` 仍仅用于案例预览视频，新增的可选 `assets` 是工程媒体白名单，每项包含 `caseId` 和上述媒体字段。两种记录共用原中间件及 `media/` 根目录；保留真实路径约束、HEAD 和 Range，不让工程里的多段原片冒充作品库已清洗预览。生产既有媒体目录挂载可承接同样的相对路径，但本轮没有执行生产挂载或配置变更。

不同源URL可以对应同一内容寻址文件：工程保留全部源引用，媒体白名单仅在同路径的SHA、字节数、MIME一致时复用文件；任一字段矛盾仍拒绝整份清单。第11工程148源引用／147物理文件已验证此路径，不能因去重丢掉第二个节点的源引用，也不能以重复路径为由使整库不可读。文件可读不授予清洗、生成或发布准入。

批量复制不会显式持有整套媒体：预校验 Blob 暂存上限为 32 MiB，超出文件按需重读，并在上传之前再次验证内容身份；单文件读取、SHA 缓冲和浏览器本身另占内存，不能把暂存上限说成总内存上限。文件读取使用 `cache:no-store`。服务进度回调只报告实际完成的唯一文件数，页面在同一个进度提示里区分核验、上传和工程保存；文件上传完成不等于工程已保存。
